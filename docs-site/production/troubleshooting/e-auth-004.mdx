When the wire's own mint threw, the message names that error in place of the
generic check list above.

`check: auth/act-as` · `error_code: E-AUTH-004` · `doctor exits: 1`

## What you're seeing

Doctor minted an away credential through your composition's `actAs` seam,
and the composition's own principal resolver did not accept it back over the
wire.

## Why

Either the mint itself errored, or the resolver rejected a credential it
should have accepted. This probe only verifies against the composition's own
resolver; it never touches your host app's separate session middleware, so a
pass here still depends on that middleware verifying real away calls
correctly.

## The fix

Start from the reason doctor's own line carries; it often names the exact
failure, a missing module or the mint's own error. Then check
`createVendo({ auth })` (or a hand-wired `actAs`), the verifier middleware on
your host API, and the host's principal resolver.

For Clerk or Auth0, confirm `VENDO_AWAY_TOKEN_SECRET` is the same value on
both sides. See [Host auth](/production/auth) for how the three auth seams fit
together.
