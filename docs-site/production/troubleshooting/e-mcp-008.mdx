# E-MCP-008

<Warning>
**what doctor prints** (broken)

MCP registry auth challenge must start with v=MCPv1
</Warning>

The deployed copy of your domain-verification file does not match what a
registry expects, even if the local copy in your repo is fine.

`check mcp/registry-auth-live` · `error_code E-MCP-008` · `doctor exits 1`

## What you're seeing

Doctor GETs `<origin>/.well-known/mcp-registry-auth` on the live deployment
and checks that the response body starts with `v=MCPv1`. This probe is
optional: doctor only reports it when the origin actually answers, since some
registries verify ownership over DNS instead of HTTP.

## Why

A deployed challenge file can drift from the one in your repo: a stale build,
a hand-edited copy on the server, or a CDN caching an old version. Whatever
the cause, the registry reads what is actually being served, not what is in
your working tree.

## The fix

Redeploy the file `npx vendo mcp verify-domain` generates (see
[E-MCP-007](/production/troubleshooting/e-mcp-007)) so the live origin serves
the same challenge as your repo. If you verify ownership over DNS instead,
this HTTP proof is not required.
