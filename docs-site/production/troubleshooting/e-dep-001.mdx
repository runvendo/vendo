```text deps/ai-sdk-major
broken: installed ai@<version> is unsupported — Vendo supports ai@6;
downgrade (npm install ai@^6 @ai-sdk/anthropic@^3 @ai-sdk/react@^3) or track
github.com/runvendo/vendo/issues/478
```

That's the message for `ai@7` and newer. An older-than-6 install gets a
different message with the same fix underneath:

```text deps/ai-sdk-major
broken: installed ai@<version> predates the ai@6 peer contract — every turn
fails at runtime; upgrade: <bump command>
```

`check: deps/ai-sdk-major` · `error_code: E-DEP-001` · `doctor exits: 1`

## What you're seeing

Every static check passes. Then every internal Vendo turn fails, because
`@vendoai/vendo` drives your `ai` package with AI SDK v6 calls, and npm
installs the peer conflict without failing on its own.

## Why

`ai@7` removed system-role messages, so v6 calls throw
`AI_InvalidPromptError`. A pre-v6 `ai` predates the v6 call shapes entirely.
The pre-v6 case is usually a hoisted copy: another package in the workspace
depends on `ai@5`, the workspace root hoists it, and your app resolves that
copy because it never declared its own.

## The fix

For `ai@7+`, downgrade to the supported major.

```bash
npm install ai@^6 @ai-sdk/anthropic@^3 @ai-sdk/react@^3
```

For a pre-v6 `ai`, give the app its own v6.

```bash
npm install ai@^6
```

In a workspace whose root pins another package's `ai@5`, an override or
packageExtension (`resolutions`, pnpm `overrides`, yarn `packageExtensions`)
also works. Re-run `npx vendo doctor` once the resolved version is v6.
