`check: machines/schedule-caller` · `error_code: E-SCHED-001` · `doctor exits: 0`

## What you're seeing

A warning: at least one app declares a schedule in its `vendo.json`, but
nothing is authorized to trigger it.

## Why

`VENDO_TICK_SECRET` is not set, so nothing can call the authenticated
`POST /api/vendo/tick` route, and the app's schedules never fire.

## The fix

Set `VENDO_TICK_SECRET` to a random secret in the server environment.

```bash .env.local
VENDO_TICK_SECRET=<a random secret>
```

Point an external cron, Vercel cron, a GitHub Actions schedule, or plain
crontab, at the tick route with that secret as a bearer token:

```bash {2}
curl -X POST https://your-app.com/api/vendo/tick \
  -H "Authorization: Bearer $VENDO_TICK_SECRET"
```

Every hit fires due schedules exactly once for that window; a double hit
from an overlapping cron is a safe no-op.
