## 1. Run init

Two things have to be in place first: a Next.js app with an
[auth preset](/deploy/auth) wired, and a model key —
`ANTHROPIC_API_KEY` in `.env.local`, or `npx vendo login` for a Cloud one.
Without the preset init says so and writes nothing; without a key `vendo_make`
has no [model to select](/deploy/model-credentials).

```bash
npx vendo init
```

Pick the MCP door path in its questions. Init writes the composition, the
catch-all route, the origin-root discovery route, and the `models:` line.
Details: [vendo init](/reference/vendo-init).

## 2. Set your origin

The door's discovery, issuer, and token audience all derive from this one
value, so it has to name the origin clients actually reach. Running locally,
that is your dev server:

```bash
# .env.local
VENDO_BASE_URL=http://localhost:3000
```

Where you deploy, set the same variable to the public origin instead. Leave it
unset either way and doctor fails with
[E-MCP-009](/deploy/troubleshooting#E-MCP-009).

## 3. Connect a client

<CodeGroup>

```bash Claude Code
# in Claude Code
/plugin marketplace add runvendo/vendo
/plugin install vendo@vendo

# in your shell, pointed at the origin you set above
export VENDO_MCP_URL=http://localhost:3000/api/vendo/mcp
```

```text Claude · ChatGPT · Cursor
https://your-app.example.com/api/vendo/mcp
```

</CodeGroup>

Whatever origin you set in step 2, plus `/api/vendo/mcp`. Hosted clients need a
public one.

The client runs the sign-in itself. Your users get a themed setup page at
`/api/vendo/mcp/connect` for free.

## 4. Ask for a screen

In the connected client, ask for something you would rather look at than read.
The agent calls `vendo_make` and gets a receipt back:

```json
{
  "id": "app_790892b0…",
  "title": "August Spending",
  "status": "ready",
  "say": "August Spending is on your screen."
}
```

The screen lands in your product, not in the chat.

## 5. Check the wiring

```bash
npx vendo doctor
```

Start your dev server first. The MCP checks fetch the door's two discovery
documents over HTTP, so a stopped server reads as a broken door. Failures name
an [E-MCP code](/deploy/troubleshooting).
