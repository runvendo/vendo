The [quickstart](/existing-agents/quickstart) wires a Mastra agent end to end.
This page is what it left out.

## The definition is static, the caller is not

One Mastra agent definition serves every user, so `vendoMastraTools` takes no
principal. Each call reads one off Mastra's request context, and a `vendo_*`
call that finds none fails closed.

```ts
// app/api/chat/route.ts
import { RequestContext } from "@mastra/core/request-context";
import { VENDO_PRINCIPAL_KEY, VENDO_SESSION_KEY } from "@vendoai/vendo/mastra";

const requestContext = new RequestContext();
requestContext.set(VENDO_PRINCIPAL_KEY, { kind: "user", subject: userId });
requestContext.set(VENDO_SESSION_KEY, hostSessionId); // optional, for audit
```

That subject has to match what your wire route's `principal` resolves, or the
person never sees what the agent makes — [one principal, two
places](/existing-agents#one-principal-two-places).

`vendoMastraTools` returns a Promise, which is why the agent takes the
tools-as-function form:

```ts
// src/mastra/agents/your-agent.ts
tools: async () => ({ ...yourTools, ...(await vendoMastraTools(vendo)) }),
```

## Warm the store first

A guarded tool can fire before any wire request has touched the store. One line
in the chat route saves you the cold-start failure:

```ts
await vendo.store.ensureSchema();
```

## Rendering the parts

Mastra streams tool calls as `dynamic-tool` or as `tool-<name>`, depending on
how the tool was declared, so match both:

```tsx
if (part.type === "dynamic-tool" || part.type.startsWith("tool-")) {
  return part.state === "output-available"
    ? <VendoToolResult output={part.output} />
    : <span>Running {part.toolName ?? part.type.slice("tool-".length)}…</span>;
}
```

Everything downstream of that is the same as any other framework
([Embeds and envelopes](/existing-agents/embeds)).
