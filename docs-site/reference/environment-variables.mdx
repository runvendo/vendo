These are the variables a host developer sets. Vendo also reads a handful of
internal test seams and harness markers that are not listed here and are not
part of any contract — if a name is not on this page, do not depend on it.

## Host process

| Variable | Effect |
| --- | --- |
| `VENDO_API_KEY` | authenticates Vendo Cloud calls (sharing, publishing, pinning) and fills any adapter slot (sandbox, store) the host left unset with the Cloud default; see [Vendo Cloud](/deploy/vendo-cloud) for adapter precedence and the data-location warning. A well-formed key also switches build and development telemetry into the cloud lane documented in the repository's [`TELEMETRY.md`](https://github.com/runvendo/vendo/blob/main/TELEMETRY.md); see [Telemetry](/deploy/telemetry#build-and-development-telemetry) |
| `VENDO_CLOUD_URL` | overrides the Vendo Cloud base URL for the runtime and CLI; defaults to `https://console.vendo.run` |
| `VENDO_TELEMETRY_DISABLED=1` | disables build and development telemetry |
| `VENDO_TICK_SECRET` | bearer secret required by `POST /tick` |
| `VENDO_BASE_URL` | trusted host origin used for server-side execution of extracted route tools, for marking the anonymous-session cookie `Secure` behind a TLS-terminating proxy, as the MCP door's canonical public base, and as the origin of the box callback URLs (`VENDO_STORE_URL`/`VENDO_HOST_URL`); machine provisioning fails without it |
| `VENDO_URL` | base URL that `vendo doctor` probes for the live `/status` check and that `vendo sync` queries for blast-radius impact; defaults to `http://localhost:3000/api/vendo`, overridden per run by `--url` |
| `VENDO_POSTHOG_KEY` · `VENDO_POSTHOG_HOST` | override the telemetry project key and the host capture events are sent to |
| `DO_NOT_TRACK=1` | disables telemetry and is also honored by Scarf |
| `CI` | disables telemetry |
| `NODE_ENV=production` | disables build and development telemetry at runtime |
| `E2B_API_KEY` | default key read by the E2B SDK when `e2bSandbox` receives no explicit `apiKey`; also auto-selects the E2B execution venue in `createVendo` when no `sandbox:` is passed and the optional `e2b` package is installed (takes precedence over the `VENDO_API_KEY` hosted sandbox default) |
| `VENDO_BOX_TEMPLATE` | provider base template a provisioned machine boots from (the box image with Node and the in-box agent harness); used by the BYO e2b path, ignored by the Cloud pool which ships its own image |
| `VENDO_BOX_EDIT_TIMEOUT_MS` | long-poll budget for one in-box agent edit; default 8 minutes |
| `VENDO_BOX_EDIT_POLL_MS` | poll interval while an in-box agent edit runs |
| `VENDO_E2B_TIMEOUT_MS` | E2B machine lifetime; when unset, a raised `VENDO_BOX_EDIT_TIMEOUT_MS` implies a matching lifetime (budget plus 5 minutes) so the provider TTL cannot kill a long build |
| `VENDO_INFERENCE_URL` · `VENDO_INFERENCE_KEY` | the in-box agent's model endpoint and key, injected into every machine; when unset, `ANTHROPIC_API_KEY` rides `https://api.anthropic.com`, then `VENDO_API_KEY` rides the Vendo Cloud model gateway, and with none of them the box gets no inference |
| `VENDO_INFERENCE_MODEL` | optional model choice passed through to the box harness |
| `VERCEL`, `CF_PAGES`, `AWS_LAMBDA_FUNCTION_NAME` | prevent the default PGlite store from opening on an ephemeral serverless filesystem; pass a Postgres URL instead |
| `VENDO_STORE_ENCRYPTION_KEY` | 32-byte base64 key the default composition uses to encrypt secret values in `vendo_secrets`; read when no store is passed to `createVendo`. An explicitly configured store ignores it |
| `VENDO_DEV_CREDENTIAL` | pins a [dev-mode credential ladder](/connect/dev-mode) rung: `env-key:anthropic` (or `:openai` / `:google`), `vendo-cloud`, or `none` |
| `VENDO_MODEL` · `VENDO_MODEL_PAINT` · `VENDO_MODEL_JUDGE` · `VENDO_MODEL_KNOWLEDGE_VERIFIER` · `VENDO_MODEL_EXTRACT` | per-slot model pins, no code change: the string passes verbatim to whatever the resolved credential talks to (the Vendo Cloud gateway with `VENDO_API_KEY`, your provider otherwise). Precedence per slot: explicit model object → env pin → `models` string → per-rung default. `VENDO_MODEL_EXTRACT` also pins the `vendo init` / `vendo sync` extraction engine; `VENDO_EXTRACTION_MODEL` is its older spelling and still works |
| `VENDO_KNOWLEDGE_VERIFY` | `on` runs the knowledge-search verifier pass, which costs a model call and seconds of latency per search; **off by default**. Any value other than on/true/1 or off/false/0 throws at compose rather than silently meaning off. The verifier resolves on the `knowledgeVerifier` model slot above; a slot that resolves to nothing simply marks results unverified |
| `VENDO_AWAY_TOKEN_SECRET` | default source for the away-token preset's shared secret — the one the producer mints with and the host's verifier checks. Pass `secret` explicitly to override it; see [actAs presets](/connect/act-as-presets) |
| `VENDO_TURN_IDLE_ABORT_MS` | how long a streaming turn may go without a client heartbeat before the server aborts it (default 15,000). Raise it on a runtime where heartbeats are unreliable; the watchdog only ever arms after a first heartbeat |
| `VENDO_APP_BUILD_WATCHDOG_MS` | how long one app build may run before it is failed with a terminal, retryable record (default 4 minutes). The client's polling cutoff derives from it, so raising this keeps the two in step |
| `VENDO_CLOUD_MODEL` | **deprecated** (use `VENDO_MODEL`) — agent-slot pin for the Vendo Cloud gateway; the gateway remaps unknown ids during the alias grace window |
| `ANTHROPIC_API_KEY` · `OPENAI_API_KEY` · `GOOGLE_GENERATIVE_AI_API_KEY` | first-preferred rung of the credential ladder read by `vendoModel()`; when set, `@vendoai/vendo/server` uses the matching `@ai-sdk/*@^3` provider installed in your app for the full native tool loop |

`VENDO_TICK_SECRET`, `VENDO_BASE_URL`, `VENDO_POSTHOG_KEY`, and the
`VENDO_BOX_*` knobs are implementation-level environment configuration. The
frozen contracts define the corresponding bearer, route origin, and telemetry
seams without requiring those names from custom compositions.

The `auth` presets read their provider's own environment rather than a
Vendo-named variable — `AUTH_SECRET` for Auth.js, `CLERK_SECRET_KEY` for
Clerk, `SUPABASE_JWT_SECRET` / `SUPABASE_URL` for Supabase,
`AUTH0_DOMAIN` (or `AUTH0_ISSUER_BASE_URL`) for Auth0. `jwt()` has no vendor
env to read and always takes an explicit secret. See
[actAs presets](/connect/act-as-presets) for the full table.

## App machine environment

The machine lifecycle injects these values into every box at provision, and
re-injects the current set (through the in-box agent control port, with an
app restart) before every in-box edit; an ordinary wake resumes the
snapshot's environment:

| Variable | Contents |
| --- | --- |
| `PORT` | port on which the app server must listen (default 8080) |
| `VENDO_STORE_URL` | base URL of the durable-rows callback surface (the wire's `/box` mount on the host origin) |
| `VENDO_HOST_URL` | base URL of the host-tools callback surface (same mount) |
| `VENDO_APP_TOKEN` | per-app bearer minted at provision; authenticates every `/box` call |
| `VENDO_INFERENCE_URL` · `VENDO_INFERENCE_KEY` | the in-box agent's model door (absent when no inference is configured) |
| `VENDO_INFERENCE_MODEL` | optional model choice the box harness reads |
| declared secret names | real values, injected only for secrets the owner granted to this app |

The `buildEnv` boundary names (all of the above except
`VENDO_INFERENCE_MODEL`, which the composition adds beside them) are
reserved; a declared secret named like one of them is a validation error. The box does its own outbound requests directly, against
the provider-enforced domain allowlist. See
[Generated UI and apps](/concepts/generated-ui#secrets-and-outbound-requests).

The `/box` callback surface authenticates every request with
`Authorization: Bearer $VENDO_APP_TOKEN` and exposes:

| Path | Methods | Purpose |
| --- | --- | --- |
| `/box/rows/<collection>` | GET | list durable rows with `refs.<key>=<value>`, `limit`, and `cursor` filters |
| `/box/rows/<collection>/<id>` | GET · PUT · DELETE | read or write one durable row; PUT body is `{data, refs?}` (JSON, 256 KB cap) |
| `/box/tools/<name>` | POST | host tool call through the guard (policy, grants, approvals, audit); body is `{args}` |

## Peer configuration

Vendo receives an AI SDK `LanguageModel`; model provider keys are configured by
that provider, not selected by a Vendo environment-variable ladder. Connector
keys are passed to connector constructors. The Cloud hosted sandbox adapter
(`cloudSandbox`, exported from `@vendoai/vendo/server`) never reads the
environment itself; `createVendo` passes it `VENDO_API_KEY` and
`VENDO_CLOUD_URL` when it fills the unset sandbox slot. See
[Vendo Cloud](/deploy/vendo-cloud) for the full setup.

The store receives its Postgres URL through `createStore({ url })` and its
PGlite directory through `createStore({ dataDir })`. Those option names are the
contract; V0 does not define storage environment-variable aliases.
