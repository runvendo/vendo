title: "The .vendo directory: tools, policy, theme, and data files"

description: "Every path inside the .vendo directory, which tool writes it, and the exact format contract, from tools.json and policy.json to theme.json and data."
---

| Path | Written by | Format |
| --- | --- | --- |
| `tools.json` | sync | `vendo/tools@3` (04) — tools with inferred field `semantics`, per-tool `srcHash`, a per-tool `enriched` marker (set by the AI enrichment pass; absent = structural defaults), and the `watermark` (git tree at the last enrichment; absent until one runs) |
| `catalog.json` | sync | `vendo/catalog@1` (04) |
| `overrides.json` | init / human | `vendo/overrides@3` (04) — per-tool overrides plus `compounds`, `briefs`, and per-surface tool menus (`surfaces.agent` / `surfaces.mcp`, see [Curate the tool menu](/capabilities/mcp#curate-the-tool-menu)) |
| `policy.json` | init / human | `vendo/policy@1` (05) |
| `remixable/<slot>.json` | sync | `PinBaseline` (06 §8) |
| `brief.md` | init | product brief for the system prompt (03 §3) |
| `design-rules.md` | host, optional | generation-time design rules (06 §5), re-read per generation so edits apply without a restart; `createVendo({ apps: { designRules } })` wins over it |
| `theme.json` | init extraction | `VendoTheme` |
| `data/` | store | PGlite files (gitignored; init writes the ignore) |
| `data/misses.jsonl` | runtime | one `vendo/capability-miss@1` event per line ([Telemetry](/deploy/telemetry#capability-misses)) |

This table is complete, and it is split by author: `tools.json` is the machine
layer `vendo sync` regenerates wholesale, and `overrides.json` is the only
hand-edited file, so extraction can never overwrite reviewed risk,
descriptions, disabled state, compounds, or briefs.

`data/` is runtime state, not configuration. Do not commit it.
